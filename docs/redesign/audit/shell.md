METHOD NOTE: Everything tagged [verified] was checked in code, by resolving the Tailwind config in node, by compiling the real globals.css with the repo's Tailwind 3.4.17 into the scratchpad (repo untouched, `git status` clean for dashboard/), or from the baseline screenshots another process saved at scratchpad/shots (1440x900 dark and light, plus 390x844 mobile). SHELL STRUCTURE [verified]: app/layout.tsx is a server component. It renders `<html lang="en" suppressHydrationWarning>` with an inline pre-paint script (layout.tsx:11-19). That script reads localStorage 'theme' and falls back to prefers-color-scheme, then adds `.dark` to <html> and sets `style.colorScheme`. <body className="font-focal ${jetbrainsMono.variable}"> contains, in order: (1) <DitherBackground/>, a `fixed inset-0 -z-10 pointer-events-none aria-hidden` wrapper around a dynamically imported (ssr:false) React Bits Dither WebGL canvas; (2) a `min-h-screen` wrapper with a translucent veil `bg-fal-gray-50/60 dark:bg-[#0a0d14]/45` (layout.tsx:38); (3) a <header> hard-coded to `bg-[#0a0d14] border-b border-fal-gray-800` in BOTH themes. The header holds a raw <img src="/wzrdtechlogo.png" class="h-9 w-auto"> (a 1717x425, 690 KB PNG of a dark-chrome blackletter 'WZRD.tech' wordmark), a divider, the <h1> 'Stream Admin' and a mono subtitle 'stream.wzrd.tech', plus ThemeToggle on the right; (4) <main class="relative max-w-7xl mx-auto px-6 lg:px-8 py-8"> containing a `.fade-in` div that wraps ConvexClientProvider and children; (5) a <footer> reading 'stream.wzrd.tech admin' / 'Powered by FAL realtime' • year. app/admin/layout.tsx puts <AdminNav/> above every admin page. AdminNav is a horizontal underline-tab bar with 7 lucide-icon tabs (Live Control, Shotboard, Characters, Locations, Clips, Recordings, Twitch Analytics) using `border-b-2 -mb-px`, `overflow-x-auto`, `aria-label="Admin sections"`. The nav sits inside <main>, so it is not sticky and scrolls away. The header is not sticky either. app/page.tsx redirects '/' to '/admin'. There is no loading.tsx, error.tsx, global-error.tsx or not-found.tsx anywhere under app/.

VISUAL LANGUAGE AS RENDERED [verified via screenshots + resolved config]: The page reads as a generic gray SaaS admin placed over a blue dithered noise field. The Dither wave is chrome/navy blue (dark: wave rgb(0.2,0.34,0.66)=#3357A8 on bg rgb(0.02,0.03,0.06)=#050810; light: wave #80A1DB on #FAFAFF; DitherBackground.tsx:103-104). It is quantized to 4 levels at 2px cells, then veiled by 45% #0a0d14 (dark) or 60% gray-50 (light). Cards (`.fal-card`) are fully opaque: white/gray-200 border/rounded-lg/shadow-sm in light, gray-900/gray-800 in dark. The Dither is therefore visible only in the gutters, behind the nav, and below short pages. The accent color is effectively VIOLET, not the chrome blue the config comment promises. tailwind.config.js defines a flat 'fal-primary' (chrome blue #7aa5e0/#4f83cc/#3a6ab0/#2d5488, lines 26-32) and then a nested `fal: { primary: {...purple} }` (lines 74-79). Tailwind's flattenColorPalette uses Object.assign, so the later nested key wins. Resolved values: fal-primary-400=#8b5cf6, 500=#6d28d9, 600=#5b21b6, 700=#4c1d95. Compiled `.fal-button-primary` has background rgb(91 33 182). The active nav tab text, input focus rings, the asset studio's 'Generate character sheet' button and every `*-fal-primary-*` usage (57x fal-primary-500) are purple. The logo, the Dither, and the flagship DitherButton 'Start Director' (dither-kit palette 'blue' [53,143,243]) are blue. Three accent families (chrome blue, Tailwind blue #3b82f6 via fal-blue, and violet) compete on every screen [opinion: this is the single biggest source of the 'unbranded' feel].

TYPOGRAPHY [verified]: Focal is self-hosted via @font-face (globals.css:5-46): Light 300 (woff2 only), Regular 400 (woff2+otf), Medium 500 (woff2+otf), Bold 700 (woff2 only), Italic 400 (OTF ONLY, 117 KB). There is no semibold 600 and no italics at other weights. body is font-weight 300 (globals.css:73). tailwind.config.js:121-128 remaps weights: normal→300, medium→400, semibold→500, bold→500, extrabold→700. So `font-semibold` and `font-bold` look the same, and Focal Bold is reachable only through `font-extrabold`, which is used 0 times. Measured usage: font-medium 98, font-semibold 33, font-bold 8, font-normal 2. Size usage is heavily skewed small: text-xs 214, text-sm 91, text-[10px] 25, text-[11px] 5, text-lg 25, text-2xl 6, text-xl 2, text-3xl 1, so roughly 75% of all text is 12px or smaller, and most of it is Light/Regular. JetBrains Mono comes from next/font/google with `variable: '--font-mono'` (layout.tsx:8), but Tailwind's `mono` family is the literal string 'JetBrains Mono' (tailwind.config.js:119) and never references var(--font-mono). next/font registers a hashed family (e.g. '__JetBrains_Mono_xxxx'), so `font-mono` text falls through to Menlo/Consolas/Liberation Mono while the webfont is still downloaded.

THEMING AND DARK MODE [verified]: Tailwind `darkMode: 'class'`. Light and dark each come from three overlapping systems: (a) unused shadcn-style CSS vars on :root (globals.css:49-63, with --primary/--accent #6d28d9); only --background/--foreground are consumed, and they are never redefined for .dark; (b) hand-written `.dark body`, `.dark *`, `.dark .fal-card`... overrides (globals.css:78-117); (c) per-element `dark:` utilities (roughly 540 across components). Because globals.css places its custom CSS after `@tailwind utilities` and outside any @layer, the compiled order is: utilities (line ~1300-2300) → custom CSS including `.dark *` (line 2572) and `.fal-*` (2680+) → variants (hover:/focus:/dark:/md:, line 2900+). That order produces real bugs (see problems). ThemeToggle and DitherBackground each track the theme independently: ThemeToggle has its own state defaulting to false, and DitherBackground uses a MutationObserver on <html class> with a default of true.

MOTION AND LOADING [verified]: The only shell motion is `.fade-in` (0.5s translateY(10px)) on the main wrapper, and it plays once on first load because the root layout persists across client navigations. There are no route transitions, no skeletons and no global loading UI. Page-level loading is inconsistent: 'Loading…' text in card headers, lucide Loader2 `animate-spin` rows, and `animate-pulse` dots in the Director. globals.css has no prefers-reduced-motion handling, and DitherBackground never passes Dither's `disableAnimation`. Reduced motion is honored only inside vendored React Bits (PixelCard, AccordionGallery, MorphSlider) and the dither-kit (pixel.ts:107 `pixelPrefersReducedMotion`, used by DitherButton).

RESPONSIVE [verified via 390px screenshot]: The header keeps the logo, divider, title and toggle in one row. The nav becomes a horizontally scrolling strip clipped mid-word ('Chara…') with no fade, snap or overflow hint. The footer's `flex justify-between` squeezes three columns into 390px ('stream.wzrd.tech / admin', 'Powered by FAL / realtime', '• 2026'). Only 48 responsive-prefixed utilities exist in the whole dashboard (sm 23, md 11, lg 8, xl 6). On short pages (Characters/Shotboard without Convex) the footer floats mid-viewport (y≈340-480 at 900px tall) with a full-bleed border line across the Dither, because the wrapper is `min-h-screen` but not a flex column.

DITHER-KIT PRIMITIVES [verified]: palette.ts has 7 named seeds (green, blue, purple, pink, orange, red, grey), each {fill,line,star} RGB. pixel.ts provides BAYER4 thresholds, FNV-1a/xorshift PRNG, hueFill (s .85, l .58), and bloom presets (off/low/high/aura, drawn as a blurred canvas copy with mix-blend plus-lighter). button.tsx's DitherButton is a native <button> with a low-res canvas fill (CELL=2), variants gradient/dotted/hatched/solid, and hover/press intensity easing. It ships its own `font-mono text-xs rounded-md` styling and a faint `focus-visible:ring-1 ring-gray-950/40`, and uses the stock Tailwind `gray-*` palette rather than fal-gray (the hex values are identical because fal-gray is a byte-for-byte copy of Tailwind gray). All of these files are hash-locked in dither-kit.json (the tripwire.sh registry), so they must be composed around, not edited. `color` also accepts a numeric hue, so it can be brand-tinted without edits.
